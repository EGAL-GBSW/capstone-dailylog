### 일주일 동안 내가 만들어 낸 것

이번 주에는 프로젝트의 전체 개발 구조와 AI 기능의 처리 흐름을 구체화하였다. 하나의 GitHub 저장소 안에서 `backend`, `frontend`, `ai`를 함께 관리하는 모노레포 구조로 진행하기로 정리하고, AI 개발은 별도 기능 브랜치와 `ai/` 폴더에서 작업할 수 있도록 개발 방향을 세웠다. 또한 사용자 음성 입력부터 STT, 사용자 확인, RAG, SLM, 주문 내용 확인, Backend 주문 처리로 이어지는 전체 서비스 흐름과 각 영역의 역할을 정리하였다.

초기 개발 단계에서는 복잡한 WebSocket이나 실시간 음성 인식보다, 사용자가 녹음을 시작하고 종료하면 생성된 음성 파일을 HTTP로 AI 서버에 전송하는 방식을 우선 적용하기로 하였다. 프론트엔드가 완성되기 전에도 테스트할 수 있도록 휴대폰으로 만든 `.m4a`, `.wav` 음성 샘플을 활용해 Whisper `base`, `small`, `medium` 모델을 비교하였다. `initial_prompt`, `beam_size=5`, `temperature=0`, `condition_on_previous_text=False` 설정을 적용해 기본 주문 문장의 인식 결과를 개선했으며, 사투리 음성에서는 `medium` 모델이 더 나은 결과를 보이는 것을 확인하였다.

배포 성능을 고려해 일반 Whisper뿐 아니라 `faster-whisper medium`도 테스트하고, 학교의 NVIDIA A4000 16GB GPU PC를 개발·테스트용 AI 서버로 활용하는 방안을 검토하였다. 키오스크에서 모델을 직접 실행하기보다 음성 데이터를 AI 서버로 보내고, 서버에서 CUDA와 `float16` 최적화를 적용해 STT를 처리하는 구조가 더 적합하다고 판단하였다.

STT 결과를 바로 주문으로 확정하지 않고, 먼저 사용자가 인식된 문장을 확인한 뒤 RAG와 SLM이 메뉴·수량·옵션·주문 의도를 구조화된 주문 후보 데이터로 만들도록 설계하였다. 이후 사용자가 주문 후보를 다시 확인하고, Backend가 실제 DB의 메뉴·가격·재고·판매 여부를 검증한 후에만 주문을 확정하도록 역할과 검증 절차를 정리하였다. 이와 함께 현재까지 분석한 내용을 바탕으로 프로젝트 분석 계획안도 작성하였다.

### 일주일 동안 겪었던 힘든 점과 해결 방법

사투리가 포함된 주문 음성에서 `base`와 `small` 모델의 인식 정확도가 충분하지 않았고, 정확도가 높은 모델을 사용할수록 처리 속도와 하드웨어 요구사항이 커지는 문제가 있었다. 또한 STT가 일부 단어를 잘못 인식했을 때 어느 단계에서 이를 보정하고 검증할지 정하는 것도 어려웠다.

이를 해결하기 위해 여러 크기의 Whisper 모델과 추론 설정을 동일한 음성 샘플로 비교하고, 사투리 인식 결과가 더 좋은 `medium` 모델을 우선 후보로 정하였다. 실행 성능은 `faster-whisper`와 GPU 서버를 활용해 보완하기로 했으며, STT의 오인식은 RAG와 SLM으로 보정하되 AI 결과를 곧바로 주문에 사용하지 않고 사용자 확인과 Backend 검증을 반드시 거치도록 전체 흐름을 설계하였다.

### 내가 잘한 점과 아쉬웠던 점

처음부터 실시간 음성 인식과 복잡한 통신 구조를 구현하려 하지 않고, 음성 파일을 HTTP로 전송하는 방식으로 초기 개발 범위를 현실적으로 정한 점을 잘했다고 생각한다. 또한 여러 STT 모델과 설정을 직접 비교하고, AI 서버와 키오스크의 역할을 분리하여 개발 환경과 향후 배포 환경까지 고려한 구조를 정리하였다. AI의 결과를 두 차례 사용자에게 확인시키고 Backend에서 최종 검증하도록 설계한 점도 서비스의 안정성을 높이는 데 도움이 될 것이라고 생각한다.

아쉬웠던 점은 현재 테스트가 제한된 수의 음성 샘플을 중심으로 진행되어 모델별 정확도와 처리 속도를 수치로 비교하지 못했다는 것이다. 앞으로는 표준어와 사투리, 다양한 메뉴명과 옵션이 포함된 테스트 데이터를 정리하고, 인식 정확도와 응답 시간을 기록하여 모델 선택의 근거를 더 명확하게 만들어야 한다. 또한 프론트엔드·백엔드와 연동할 API 형식과 주문 후보 JSON 구조도 팀원들과 더 구체적으로 합의할 필요가 있다.
